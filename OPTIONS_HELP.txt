View options:
    --fullscreen
        Display the app in full screen. The default is to display in a window
        instead, except on Android which always uses full screen.

        The app's output will be scaled to fit your screen. This is independent
        of the internal resolution, so if the scale hack (see below) is not also
        in use, the result may be a bit blurry. An internal resolution larger
        than your screen's is possible, in which case the output is downscaled.

    --aspect=...
        How the app's screen is fitted into the screen in full screen mode
        (including on Android). One of:
        - fit: keep the aspect ratio, with black bars on two sides (default)
        - stretch: fill the whole screen, distorting the image
        - fill: keep the aspect ratio and fill the whole screen, cropping the
          edges that don't fit
        - integer: keep the aspect ratio and only scale by whole numbers, so
          all pixels have the same size (may leave larger black bars)

    --filter=...
        How the app's screen is filtered when scaled up. One of:
        - smooth: bilinear filtering (default, except on Android). Can look
          blurry.
        - sharp: scale up by a whole number keeping pixels crisp, then smoothly
          for the rest. Recommended for pixel art on large screens. This is
          the default on Android.
        - pixel: nearest-neighbour filtering only. Crisp, but pixels may have
          uneven sizes unless --aspect=integer is used.
        - hq: like sharp, but images the app draws without OpenGL ES (e.g.
          2D games that draw with Core Graphics) are first scaled up with a
          pixel art scaling algorithm (Scale2x), rounding off jagged edges.

    --keep-screen-on
    --no-keep-screen-on
        Whether to keep the screen on (prevent the screen saver, or on Android,
        the screen turning off) while touchHLE is running, even if the app
        doesn't ask for it. The default is to keep it on on Android, and
        otherwise to let the app decide, like iPhone OS does.

    --upside-down
    --landscape-left
    --landscape-right
        Changes the orientation the virtual device will have at startup.
        The default is portrait.

        --upside-down means rotate 180° from portrait.
        --landscape-left means rotate 90° counterclockwise from portrait.
        --landscape-right means rotate 90° clockwise from portrait.

        Usually apps that require landscape mode will tell touchHLE about this,
        and it will automatically rotate the window, but some apps neglect to
        do this. These options may be useful in that case.

    --subpixel-offset=...
        Shifts everything the app draws right by this much, e.g. 0.01, in the
        app's own coordinates (usually points, for 2D drawing).
        Some apps draw quads exactly between pixels, and which texel is used
        then differs between GPUs, which can e.g. cut off a column of some
        letters. A tiny shift makes the result match the iPhone. Only use this
        for apps that need it.

    --scale-hack=...
        Set a scaling factor for the window. touchHLE will attempt to run the
        app with an increased internal resolution. This is a hack and there's
        no guarantee it will work correctly for all apps.

        The default is no scale hack, which is equivalent to a value of 1 (i.e.
        a scale of 1×).

        This is a natural number that is at least 1.

Device options:
    --device-family=...
        Specifies which device family should be emulated: iPhone or iPad.
        This only work if running app does support selected family
        (or the option will be ignored).

        If omitted, suitable device family would be deduced from application
        bundle itself, falling back to iPhone if needed.

        Accepted values are "iphone" and "ipad" respectively.

    --device-model=...
        Specifies which device model the app is told it runs on, e.g.
        iPhone2,1 (iPhone 3GS). Legacy phone geometry defaults to iPhone1,1;
        automatic or manual device profiles can select a different model.
        Some apps refuse to run on older models, but others use
        features touchHLE doesn't support (like OpenGL ES 2.0) on newer ones,
        so only change this for apps that need it.

    --device-profile=auto|MACHINE
        Selects a device profile by machine ID, or automatically selects one
        using the app's supported device families, widescreen support and host
        display. Defaults to auto. The app picker retains its legacy geometry.
        The profile resolves the model, family, Retina scale and logical screen
        size at runtime. Examples: iPhone5,1 (iPhone 5), iPhone7,2 (iPhone 6,
        750x1334), iPhone7,1 (iPhone 6 Plus, 1242x2208 at 3x). Large phone
        canvases require the app's launch-image opt-in; otherwise a compatible
        2x canvas is used. Auto prefers the existing lower-resolution profile
        when aspect ratios differ by less than 0.5%.

    --system-version=...
        Sets the operating system version reported by UIDevice.systemVersion.
        The default is 2.0. Accepts 1 to 3 dot-separated decimal numbers, each
        from 0 to 65535, for example 7, 7.0 or 7.0.1. This can enable an app's
        version-gated features; it does not add missing operating system APIs.

    --retina
        Tells the app the screen is a Retina display (twice the resolution in
        each direction, like the iPhone 4's). Apps that support it can then
        render at the higher resolution. Use it together with a
        --device-model= that has a Retina display, e.g. iPhone4,1.

Game controller options:
    --deadzone=...
        Configures the size of the \"dead zone\" for analog stick inputs.

        The default value is 0.1, which means that 10% of the stick's range on
        the X and Y axes around the center position will be collapsed into a
        single point, so that movements in that range are ignored.

        This is a floating-point (decimal) number between 0 and 1.

    --disable-analog-stick-tilt-controls
        Disables mapping of analog stick input to simulated rotation of the
        device.

        By default, if touchHLE detects a game controller, its analog sticks
        will be used for simulated accelerometer tilt controls. When this
        happens, the real accelerometer (e.g. on an Android phone), if present,
        is ignored. By setting this option, the real accelerometer can be used
        even if a game controller is detected. This may be useful on a device
        that integrates both an accelerometer and a game controller, or if you
        do not want to disconnect your game controller.

        Note that touchHLE does not currently support accelerometers contained
        within game controllers.

    --x-tilt-range=...
    --y-tilt-range=...
        Set the simulated rotation range of the device axis mapped to the analog
        stick X or Y axis, or to the mouse cursor's X or Y position within the
        window (when the right mouse button is held).

        Positive X and Y are mapped to tilting the device rightward and forward
        respectively.

        By default, an analog stick's axis is mapped to a rotation range of 60°
        (30° in either direction). If you wanted a range of 90° on the X axis,
        you could use --x-tilt-range=90.

        For historical reasons, the device's X axis is mapped to the analog
        stick's Y axis and vice versa, as if the device is held in landscape.

        This is a floating-point (decimal) number of degrees, without a degree
        symbol. It may be negative.

    --x-tilt-offset=...
    --y-tilt-offset=...
        Offset the simulated angle of the device axis mapped to the analog stick
        X or Y axis, or to the mouse cursor's X or Y position within the window
        (when the right mouse button is held).

        Positive X and Y are mapped to tilting the device rightward and forward
        respectively.

        By default, the device is simulated as being level with the ground when
        the stick is in the center/neutral position. This option is intended for
        games that use a different angle relative to the ground as their neutral
        position. For example, if a game expects you to hold the device in a
        landscape orientation, with a 45° angle to the ground, you might use
        --y-tilt-offset=45.

        This is a floating-point (decimal) number of degrees, without a degree
        symbol. It may be negative.

    --touch-map-size=W,H
        Sets the coordinate reference for all controller touch mappings. Both
        dimensions must be positive integers. This reference is relative to the
        current orientation: 480,320 describes a landscape layout. Coordinates
        are normalized and rotated onto the selected device's logical screen.
        Without this option, mappings retain the family's legacy reference
        (iPhone 320x480 portrait or 480x320 landscape), even on taller profiles.
        This does not change mouse or physical touch coordinates.

    --button-to-touch=...
        Maps a button on a game controller to a point on the simulated touch
        screen of the device. Pressing the button will behave like touching that
        part of the screen.

        This is three parts separated by commas: the name of a button (DPadLeft,
        DPadUp, DPadRight, DPadDown, Start, Back, LeftShoulder, RightShoulder,
        LeftStick, RightStick, LeftTrigger, RightTrigger or Xbox-like A, B, X
        or Y), the X co-ordinate and the Y co-ordinate.
        The co-ordinates are floating-point (decimal) numbers. 0,0 is the
        top-left corner. The bottom-right corner is 320,480 if the app is in
        portrait, and 480,320 if the app is in landscape.

        For example, --button-to-touch=A,470,310 will make the A button simulate
        tapping in the bottom-right corner of the screen, for a landscape game.

        Except where specified in touchHLE_default_options.txt, this is not used
        by default. There is however a virtual cursor that is controlled by the
        right analog stick (tap/hold by pressing the stick or right shoulder
        button).

        Triggers press at 50% travel and release below 40% to avoid noise.
        Mapping RightStick or RightShoulder disables the virtual cursor.
        Disconnecting a controller releases synthetic controller touches.

    --right-stick-to-touch=X,Y,WIDTH,HEIGHT
        Maps the right stick to a touch region, using the same co-ordinates as
        --stick-to-touch. Width and height must be positive. Moving out of the
        deadzone presses and moves a touch; returning to center releases it.
        Disables the right-stick virtual cursor. Useful for camera touch areas;
        this is an absolute region mapping, not continuous swipe emulation.
        Native GameController input disables controller touch, cursor and tilt
        simulation while keeping host controller state available to the app.

    --dpad-to-touch=...
        Maps a D-pad on a game controller to simulated finger movement within a
        region of the simulated touch screen of the device. This is useful for
        games where diagonals are used.

        This is four parts separated by commas: x,y,w,h. The co-ordinates
        are floating-point (decimal) numbers. 0,0 is the top-left corner. The
        bottom-right corner is 320,480 if the app is in portrait, and 480,320
        if the app is in landscape.

        For example, --dpad-to-touch=10,10,50,50 will simulate an 8-directional
        D-pad within a 50x50 pixel region starting at (10,10) on the screen.

        Note that this option takes precedence over any D-pad buttons defined
        with --button-to-touch.

        Except where specified in touchHLE_default_options.txt, this is not used
        by default. There is however a virtual cursor that is controlled by the
        right analog stick (tap/hold by pressing the stick or right shoulder
        button).

    --stick-to-touch=...
        Maps the left analog stick to simulated finger movement within a region
        of the simulated touch screen of the device. This is useful for games
        which use analog movement controls.

        This is four parts separated by commas: x,y,w,h. The co-ordinates
        are floating-point (decimal) numbers. 0,0 is the top-left corner. The
        bottom-right corner is 320,480 if the app is in portrait, and 480,320
        if the app is in landscape.

        For example, --stick-to-touch=10,10,100,100 will map the left analog
        stick to control a touch within a 100x100 pixel region starting at
        (10,10) on the screen.

        Except where specified in touchHLE_default_options.txt, this is not used
        by default. There is however a virtual cursor that is controlled by the
        right analog stick (tap/hold by pressing the stick or right shoulder
        button).

    --stick-touch-start-at-center
        With --stick-to-touch, begin each left-stick gesture with TouchDown at
        the region center followed by TouchMove to the deflected position.
        Useful for dynamic joysticks that take the initial touch as their origin.
        Off by default; enabled in the GTA Vice City profile only.

    --right-stick-swipe=X,Y,WIDTH,HEIGHT
        Continuously swipe for camera control while the right stick is held.
        Starts at the region center, then moves at up to 160 logical pixels per
        second per axis. Each poll integrates at most 50ms. At a region boundary,
        releases and starts again at the center, avoiding a backwards drag.
        Releases in the deadzone, on focus loss, disconnect or native mode.
        Width and height must be positive finite numbers. Uses the same logical
        co-ordinates as --stick-to-touch and disables the virtual cursor.
        Separate from --right-stick-to-touch; the last of these options wins.

    --stabilize-virtual-cursor=...
        Apply motion smoothing and a sticky radius to the virtual cursor
        (controlled by the right analog stick).

        Some apps are very sensitive to small finger movements and will always
        register an attempted "tap" as a scrolling gesture if the finger moves
        even very slightly. When combined with the low precision and shakiness
        of the virtual cursor, it can be difficult to use certain apps' menus.
        This option exists to compensate for this.

        The value is two floating-point (decimal) numbers separated by a comma.
        The first is the strength of the motion smoothing, and the second is a
        radius, in pixels, within which movement of the cursor will be ignored.
        To increase these values is to trade off responsiveness and precision
        respectively. Either number can be zero if desired. Note that the effect
        of the sticky radius is *not* shown on-screen!

        For example, --stabilize-virtual-cursor=0.1,10 will smooth out movements
        such that sharp movements take about half a second to complete, while
        movements within a 10px radius will be completely ignored.

Graphics driver options:
    --gles1=...
        Force touchHLE to use a particular OpenGL ES 1.1 implementation.
        This may be useful for troubleshooting graphics driver issues.

        --gles1=gles1_on_gl2 will use touchHLE's GLES1-on-GL2 layer.
        --gles1=gles1_native will use native OpenGL ES 1.1.

        When this option isn't in use, touchHLE will try each in order and use
        the first one that works.

Debugging options:
    --disable-direct-memory-access
        Force dynarmic to always access guest memory via the memory access
        callbacks, rather than using the fast direct access path (page tables).

    --gdb=...
        Starts touchHLE in debugging mode, listening for GDB remote serial
        protocol connections over TCP on the specified host and port.

        You can then connect to touchHLE with GDB and make use of its features
        to inspect memory and registers, set up software breakpoints, and
        continue or step execution.

        The host and port should be separated by a colon. The host can be a
        host name or an IP address. IPv6 addresses should be enclosed in square
        brackets, e.g. --gdb=[::1]:9001 for IPv6 loopback device port 9001.

    --no-error-popup
        Disables the graphical error message box (outputs to terminal/log file
        only).

    --dump=...
        Dumps some information about app/emulator to dump file. Check
        src/options.rs:parse_dump_options for the currently available options.

    --dump-file=...
        Pick the file for information to be dumped to, relative to the user
        data directory. Defaults to {user directory}/DUMP.txt. Note that this
        file will get truncated (deleted) if it already exists!

Other options:
    --preferred-languages=...
        Specifies a list of preferred languages to be reported to the app.

        This should be one or more ISO 639 language codes (usually two letters)
        in order of preference, separated by commas. For example,
        --preferred-languages=de,ja,en means you would prefer German, or failing
        that Japanese, or failing that English.

        If this option is not specified, the list comes from your operating
        system's language settings.

        Whether and how this preference is respected, and whether any particular
        language is supported, is determined entirely by the app.

    --headless
        Run in headless mode. touchHLE will not create a window, so there will
        be no graphical output and no input. Only useful for command-line apps.
        Implies --no-error-popup.

    --args
        All arguments following this option will be passed to the app (via C's
        argc/argv) rather than processed by touchHLE. This option can't be used
        via touchHLE_options.txt or touchHLE_default_options.txt.

    --audio-test=original|smooth-edges|lower-volume
        GTA Vice City sound comparisons, also in its Android long-press menu.
        Processes only mono 16-bit effects lasting 10ms to 2s. Stereo music and
        streaming queues retain the original samples. Smooth edges applies a
        2ms ramp at each end; lower volume halves the samples. Both are
        experimental comparisons, disabled on ordinary launches. A few audio
        events append to touchHLE_performance_tests.txt without enabling frame
        timing. The Android game screen has a noise marker button in these
        modes. Tap immediately after hearing noise: a bounded history of up to
        192 recent source events (within 15s), current source state and the next
        3s of events append to the report. Recent uploaded PCM (at most 6s /
        4 MiB, up to 8 captures per run) is saved under touchHLE_audio_captures.
        This does not record microphone input. Capturing may briefly stall
        playback. Ordinary launches do not keep this history. Original game files and
        saved settings are never modified.

    --performance-test=reference|low-resolution|quiet-log|low-resolution-quiet-log
        Opt-in comparison diagnostics, available from GTA Vice City's Android
        long-press menu. Tests use 1x scaling, sharp filtering and a 60fps cap.
        Low-resolution modes disable Retina without changing device identity.
        Quiet modes suppress only short-read warnings, not actual I/O errors.
        Reports append every 5 seconds to touchHLE_performance_tests.txt.
        CPU and GL submission timings add diagnostic overhead and measure host
        wall time, not asynchronous GPU execution. Readback is part of present
        time. Use the same gameplay scene for each mode; no settings are saved.

    --print-fps
        Logs the current framerate (FPS) to the console once per second.
        For apps that draw with UIKit or Core Graphics, this counts the frames
        that touchHLE actually draws, which is lower than 60 when the app's
        content doesn't change on every frame.

    --fps-limit=...
        Modify or disable the framerate (FPS) limit.

        By default, touchHLE limits the framerate of an app to 60fps, because
        this is required for accurate emulation. Some apps can however run
        correctly at a higher framerate than normal.

        This is either 'off', to disable the framerate limit, or otherwise
        a floating-point (decimal) number of frames per second.

        Note that many apps have an internal timer that determines how often
        they present frames; increasing the limit will not increase their
        framerate, but may make it less consistent.

    --force-composition
        Forces presentation of renderbuffer as if no fullscreen EAGL layer is
        present, i.e. renderbuffer will go through the compositor.

        Enabling this option may solve some rendering issues, but implies
        a performance hit which is undesirable in most of the cases.

    --gamekit-host=IP:PORT / --gamekit-join=IP:PORT
        Opt in to local-only historical GameKit. Requires --allow-network-access.
        Host binds TCP and UDP; join connects to that Host.
    --gamekit-bind=IP:PORT
        Override the local listener (Client default 0.0.0.0:0).
    --gamekit-player-id=UUID
        Stable local identity; otherwise generated for this emulator instance.
    --gamekit-timeout-ms=N
        Matchmaking timeout, 100..300000 ms (default 30000).

    --gamekit-room=NAME
        With --gamekit-host, advertise the actual GameKit room on the LAN
        while accepting players. No discovery packets are sent by default.
    --gamekit-discover=auto|ROOM_UUID
        Find a compatible GameKit room instead of --gamekit-join. Auto waits
        one second to collect announcements and rejects an ambiguous list.
        Connection still requires real peers and matching GameKit attributes.
    --gamekit-auto
        Local GameKit without choosing a role: when the app looks for players,
        join a compatible room found on the LAN, or else host one (named by
        --gamekit-room, or "UFtouchHLE") and advertise it. Requires
        --allow-network-access. An explicit host, join or discover option
        overrides it. On by default for Monster Hunter Portable 2nd G.
    --gamekit-discovery-bind=IP:PORT
        Discovery browser UDP bind (default 0.0.0.0:42019).
    --gamekit-broadcast=IP:PORT
        Host advertisement destination; repeat for multiple interfaces or
        local test browsers. Default 255.255.255.255:42019.

    --network-trace[=on|off]
        Log observed network API calls and callback activity as [NetworkTrace]
        JSON records in touchHLE_log.txt. Off by default. Does not enable network
        access or implement GameKit. Diagnostic logging may slow games down.

    --mhp2g-save-research
        For researching MHP2G's save format: dump the save data, the buffers
        around its encryption and accesses to them to /tmp/touchhle_dump. Off by
        default. Slows down every app, and does nothing useful on Android.

    --network-trace-limit=<positive integer>
        Limit network trace records (default: 50000), followed by one truncation
        marker. Does not enable tracing by itself.

    --allow-network-access
        Allow apps running in touchHLE to access the Internet and the local network.

    --ignore-gl-errors
        Ignore host OpenGL errors as queried by glGetError function.
        This only affects return value of glGetError as seen by the guest
        and nothing else. Should be enabled only for apps which really
        need this behaviour.

    --trace-gl-errors
        Check for an OpenGL ES error after every call the app makes and log
        where it happened. For debugging only: the app no longer sees errors.

    --verbose-gles
        Log every OpenGL ES call the app makes. For debugging only.

    --prefer-gles2-context
        Create an OpenGL ES 2.0 context when the app asks for OpenGL ES 1.1.
        Only for apps that ask for 1.1 but use the 2.0 shader functions.

    --force-gles1-context
        Create an OpenGL ES 1.1 context when the app asks for OpenGL ES 2.0 or
        3.0. Only for engines that fall back to 1.1 rendering.

    --fix-texture-min-filter
    --no-fix-texture-min-filter
        Whether to use linear minification for textures without mipmaps when
        the app never set a filter, so they aren't drawn black or white. On by
        default on Android.

    --reverse-attrib-locations
        If an OpenGL ES 2.0 app binds no attribute locations itself, number a
        program's attributes 0 to N-1 in the reverse of the host driver's
        order. Needed by Noblemen: 1896.

    --zero-stack-after-guest-to-host-call=<bytes>
        After a guest-to-host call returns, zero out the given number of
        bytes immediately below the current stack pointer (i.e. the unused
        scratch region of the guest's full-descending stack).
        This option exists because a guest-to-host call leaves that region
        untouched, whereas a real call on iOS could leave it in a "dirty"
        state. This can make a difference for apps that store data on the
        stack and branch based on the stack's content. There is normally
        no reason to enable this option. The number of bytes must be
        chosen carefully on a per-app basis.

--p2g-wide-screen
    Experimental expanded 3D view for P2G (jp.co.capcom.mhp2gjp 1.00.02).
    Retains the original centered 568x320-point UI and touch coordinates.
    Extends the scene to the host phone aspect (up to 2.5:1); on a narrower
    desktop display, uses approximately 19.5:9. Uses the iPhone 5 Retina canvas.
    Unsupported executables are rejected; other games are not affected.
